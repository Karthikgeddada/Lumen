# Lumen Python Pipelines

Open-source Python sidecar service for Lumen. One **pipeline module per
workspace nav item**, built individually:

| Module | Pipeline | Status |
| --- | --- | --- |
| 1. Document Library | **Parsing engine** — pdfplumber (text + font-size heading detection + tables), python-docx (true body order), openpyxl (values **and** formulas with cell refs), pandas (CSV) | ✅ built · wired into the Node worker (2026-11-26) |
| 2. Data Extraction | Field-extraction engine on top of #1 | planned |
| 3. Analytics | pandas stats + chart-ready aggregates | planned |
| 4. AI Assistant | Local RAG (sentence-transformers + FAISS) | planned |
| 5. Questionnaires | Scoring / consistency engine | planned |

All dependencies are permissive open-source licenses (BSD/MIT/Apache). No
cloud accounts, no API keys, no paid services.

## Run locally

```bash
cd python-pipelines
pip install -r requirements.txt
uvicorn main:app --port 8100
# smoke test (raw body — no multipart dependency at all):
curl --data-binary @some.pdf -H "Content-Type: application/octet-stream" \
     "localhost:8100/parse?name=some.pdf"
```

## Deploy (Render)

`render.yaml` already contains the `lumen-pipelines` web service (free
tier, singapore). After the first deploy:

1. Copy its URL (e.g. `https://lumen-pipelines-xxxx.onrender.com`)
2. Add to the **lumen-api** service Environment tab:
   - `PARSE_SERVICE_URL` = the URL above
   - `PIPELINES_TOKEN` = the value Render generated for the pipelines service

Free-tier note: the service sleeps after ~15 min idle, so the first parse
after a gap pays a ~50 s cold start; the Node worker falls back to its
JS parsers if the service is unreachable or slow, so uploads never fail
because of Python. **Wired 2026-11-26:** `parseDocument()` now calls
`/parse` first for pdf/docx/xlsx/csv (when `PARSE_SERVICE_URL` is set) and
falls back with a logged reason on every failure mode — this is live code,
not a plan.

## Contract

`POST /parse?name=<filename>` with the file as the **raw request body**
(`application/octet-stream` — no multipart library needed) returns the
exact JSON shape the Node pipeline consumes (`pageCount`, `ocrRequired`,
`sections[]`, `tables[]`), so integrating it is a drop-in swap inside
`parseDocument()`.

PDF table attribution (verified against a financial-statement fixture,
2026-11-26): each table gets a title from its own single-cell title row if
it has one ("Balance Sheets (In thousands)"), else from the nearest text
line **above** the table — never a heading from below it — and table
content is kept out of `sections` so it is never double-reported (it is
already chunked as table rows by the Node pipeline).

Caveat (verified): formula cells keep their provenance (`ref` + `f`), and
the computed value `v` comes from the cache the *saving application*
wrote. Excel/LibreOffice files carry it; files generated by openpyxl
itself do not (openpyxl never computes formulas — same limitation as the
previous JS parser).
