# Lumen Python Pipelines

Open-source Python sidecar service for Lumen. One **pipeline module per
workspace nav item**, built individually:

| Module | Pipeline | Status |
| --- | --- | --- |
| 1. Document Library | **Parsing engine** — pdfplumber (text + font-size heading detection + tables), python-docx (true body order), openpyxl (values **and** formulas with cell refs), pandas (CSV) | ✅ built |
| 2. Data Extraction | Field-extraction engine on top of #1 | planned |
| 3. Analytics | pandas stats + chart-ready aggregates | planned |
| 4. AI Assistant | Local RAG (sentence-transformers + FAISS) | planned |
| 5. Questionnaires | Scoring / consistency engine | planned |

All dependencies are permissive open-source licenses (BSD/MIT/Apache). No
cloud accounts, no API keys, no paid services.

## Run locally

```bash
cd python-pipelines
pip install -r requirements.txt
uvicorn main:app --port 8100
# smoke test:
curl -F file=@some.pdf localhost:8100/parse
```

## Deploy (Render)

`render.yaml` already contains the `lumen-pipelines` web service (free
tier, singapore). After the first deploy:

1. Copy its URL (e.g. `https://lumen-pipelines-xxxx.onrender.com`)
2. Add to the **lumen-api** service Environment tab:
   - `PARSE_SERVICE_URL` = the URL above
   - `PIPELINES_TOKEN` = the value Render generated for the pipelines service

Free-tier note: the service sleeps after ~15 min idle, so the first parse
after a gap pays a ~50 s cold start; the Node worker falls back to its
JS parsers if the service is unreachable or slow, so uploads never fail
because of Python.

## Contract

`POST /parse` (multipart `file`) returns the exact JSON shape the Node
pipeline consumes (`pageCount`, `ocrRequired`, `sections[]`, `tables[]`),
so integrating it is a drop-in swap inside `parseDocument()`.

Caveat (verified): formula cells keep their provenance (`ref` + `f`), and
the computed value `v` comes from the cache the *saving application*
wrote. Excel/LibreOffice files carry it; files generated by openpyxl
itself do not (openpyxl never computes formulas — same limitation as the
previous JS parser).
